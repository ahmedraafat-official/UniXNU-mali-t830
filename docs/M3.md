# M3 (first write) — T830 software reset

Date: 2026-11-18. Device: SM-T585 (`gtaxllte`). The read-only M2 probe was
extended with the Panfrost v5 software-reset sequence, gated behind
`gtaxllte-mali-reset=1`. The sequence is the first write to the GPU:

```text
GPU_INT_MASK  (0x28) <- 0x00000000
GPU_INT_CLEAR (0x24) <- 0x00000100   reset-completed bit
GPU_CMD       (0x30) <- 0x00000001   GPU_CMD_SOFT_RESET
poll GPU_INT_RAWSTAT (0x20) & 0x100
GPU_INT_CLEAR (0x24) <- 0x00030781
GPU_INT_MASK  (0x28) <- 0x00000081
```

## Result

```text
pd=0x0000000f/0x0003000f            G3D domain on
cmu=0x00200000/0x00000000/0x000001ff/0x0000007f
gpu=0x08300010                      T830 0x0830 r0p1
l2=0x07100206
core=0x00000000
reset=0                             soft reset completed
raw=0x00000100                      RESET_COMPLETED set
```

Photograph: `phase0/mali2-r270.jpg` in the gtaxllte workspace.

The T830 accepts the Panfrost v5 reset sequence with no hard-reset fallback.
The GPU_ID remains the same after the reset.

## Limits

This is one register-only write sequence; it does not enable the MMU, allocate
a BO or submit a job. The next step is the G52 NativeMali JM port with the T830
model (already added to the fork) and the Midgard v5 job header, then MMU enable
and one `WRITE_VALUE` job with a software fence.
